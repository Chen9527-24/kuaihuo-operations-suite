# UCP 工作台操作与运行管理

本说明介绍已经接入主窗口的操作：登录、选择机器人、启停、授权状态、等待、日志和本地记录。
机器人创建、客服知识和规则维护在PC完成；UCP主要读取配置并执行平台操作，不是本地机器人配置管理器。
安装与变量见[配置说明](CONFIGURATION.md)，业务链路见[自动回复](../../docs/features/AUTO_REPLY.md)。
当前真实工作台使用 `TopBar` 与 `AccountListPanel`；抖音、视频号可选择，快手与小红书显示未实现并禁用，控制器也拒绝这两个平台。

## 第一次进入工作台

1. 先在自己的Core创建可用操作员、租户及相应机器人，按自己的部署完成PC配置。
2. 复制 `.env.example` 为 `.env`，填写自己的Core服务根地址，启动 `python run.py`。
3. 在UCP登录页输入Core账号。需要保存凭据时再勾选记住选项；缓存采用可逆编码，不是系统加密凭据库。
4. 多租户账号手动登录后需要显式选择工作空间；单租户可进入对应空间；没有可用租户不能进入工作台。
5. 进入后在顶部选平台、左侧选“私信”或“评论”，点击刷新取得对应机器人列表。
6. 点击机器人卡片选择对象，核对绑定账号、到期时间和当前状态，再启动需要的机器人。
7. 按平台页面要求自行扫码/登录；Core登录与平台登录是两次不同的身份确认。

UCP不附带可用的真实平台账号或Cookie。资料显示了账号名称，不等于执行电脑已经登录这个平台账号。
缺失的config、profiles、records目录会按运行需要创建，不要求恢复原项目里的真实账号JSON或旧会话。

## 下次启动和租户恢复

有GUI会话缓存时，UCP尝试用刷新Token恢复Core登录；上次选择的租户仍有效时可以沿用。
需要重新选择时进入租户页；恢复失败会清除该GUI会话缓存并回到登录页。
记住用户名/密码的偏好与GUI刷新Token缓存是不同记录，不要把输入框预填理解成已经取得有效登录会话。

顶部“退出登录”退出当前Core会话并停止已有本地控制器，清理GUI会话缓存，回到登录页。
平台浏览器Profile不会因此被删除；此前选择保存的登录凭据也不等于全部被清空。
需要换租户或账号时，先停止运行，退出Core登录后重新进入，核对列表属于目标空间。
依据：[登录与恢复](../app/main_window.py#L248)、[退出Core](../app/main_window.py#L280)。

## 工作台有哪些操作

| 入口 | 当前行为 |
| --- | --- |
| 顶部平台 | 切换平台范围；未实现平台按钮不可用 |
| 左侧私信/评论 | 切换当前平台下的机器人分类 |
| 刷新 | 重新读取后端列表和可取得的状态 |
| 机器人卡片 | 显示名称、分类、绑定账号、到期与本地运行状态 |
| 卡片启动/停止 | 控制这台电脑中的相应平台控制器 |
| 卡片日志 | 查看此机器人日志与接口请求；后台关闭诊断时可能隐藏 |
| 右侧网页区域 | 展示选中机器人的页面/预览，具体方式随平台实现不同 |
| 顶部退出登录 | 退出Core账号，与退出平台账号不同 |

切换列表不等于批量停止其他机器人；不同对象的控制器和日志按机器人标识管理。
同平台同名账号可能复用浏览器登录资料，但不代表共用所有扫描、调度和发送状态。
卡片详情和可用按钮受机器人、设备、到期及当前运行状态影响；不要绕过禁用按钮推断仍可正常发送。

当前主卡片没有接通“退出平台账号”按钮，虽然源码保留相关方法；不要寻找文档中不存在的一键平台退出向导。
如需迁移或清理平台Profile，先停止相关机器人并关闭程序，妥善处理本机私有目录；这也不等于调用平台服务撤销所有远端会话。
依据：[主界面接线](../app/main_window.py#L180)、[卡片](../app/widgets/account_list.py#L183)。

## 启动、停止、远端状态和关闭窗口

点击启动时，客户端重新读取本次自动回复设置，建立对应控制器并打开预览，随后同步运行状态。
它不是调用Core的start接口远程启动另一台电脑；日志会记录本地启动及状态回写。
如果过期或当前状态不允许启动，客户端会提示并拒绝执行。

点击停止时停止本地控制器并尽量把运行状态回写为STOPPED；停止失败或回写失败会留日志。
程序运行中约每30秒检查已运行机器人的后端状态。发现STOPPING、STOPPED、DISABLED、ERROR、EXPIRED或到期时，可停止本地控制器并回写相应结果。
这是轮询同步，不能理解为PC点击停止瞬间所有平台动作都一定已经结束。

关闭UCP窗口时会尝试停止本地机器人、同步停止状态、释放WebEngine，并让记录服务完成关闭处理。
进程被强制结束、网络失败或机器断电时，不保证每个停止回写及记录写入都完成。
关闭UCP后没有独立后台守护程序替它继续采集和发送。
依据：[启停实现](../app/main_window.py#L535)、[后端状态监视](../app/main_window.py#L795)、[窗口关闭](../app/main_window.py#L1323)。

## 平台授权、设备资料与PC扫码入口

需要分清四层信息：Core操作员、客服账号资料、机器人关联的授权/设备记录、本机真正的平台浏览器登录态。
前两层描述使用者与客服身份；后两层才与执行位置和平台会话有关。

- UCP读取机器人已有的device/auth关联，可触碰设备在线状态并回写授权状态。
- 启动控制器本身不抢先把授权降级成WAIT_QR；只有页面明确进入登录/扫码等待时才回写。
- 平台模块就绪或确认扫码后，才按实际检测结果同步AUTHORIZED及有限的会话摘要。
- 授权回写失败应核对Core权限、网络与关联记录，不等同于平台一定退出登录。
- 登录Profile保存在本机，不因为后台显示已授权就自动出现在另一台电脑。

当前UCP没有接通设备配对码输入、设备注册向导或通用的auth-session二维码上报/完成界面。
PC中存在创建扫码会话的接口/按钮，不代表当前桌面已经完整实现“收到扫码会话→自动上报二维码”链路。
自行部署时，按实际PC/后端配置建立关联，再在UCP中完成平台页面登录；不要用未实现的配对流程代替本机授权验收。
依据：[设备状态与授权接口](../app/services/core_nexus_service.py#L136)、[页面状态回写](../app/main_window.py#L724)。

## 启动了但暂时没有回复：先看运行等待

扫描频率、工作时段、业务冷却和系统睡眠是不同概念。
`.env`中的DM_ACTIVE/IDLE等毫秒参数主要控制检测节奏，不等于所有客户都会在该间隔内得到回复。
机器人 `config.runtimePolicy`还可设置时区、硬休眠、工作窗口、空轮等待和回复后/错误后冷却。
这些业务策略由后端机器人配置读取，运行控制器会周期刷新；修改后端不代表任意执行阶段即时全部重置。

| 策略 | 用途 | 观察方式 |
| --- | --- | --- |
| `hardSleep` | 指定夜间休眠及唤醒时间窗口，优先于普通业务窗口 | 日志可出现hard_sleep和剩余等待秒数 |
| `scheduleMode`与DM/评论窗口 | 决定何时允许开始相应业务扫描 | 日志可出现waiting_dm_window或waiting_comment_window |
| 回复后冷却 | 一轮回复后等待，减少马上进入下一轮 | 结合cooldown原因与运行状态判断 |
| 空轮和错误等待 | 无候选或失败后调整下一次处理节奏 | 结合空轮/错误日志，而非只看是否有新回复 |
| `enabled=false` | 关闭该运行节奏控制器的等待判断 | 不等于关闭业务机器人或取得无限发送许可 |

源码有默认策略，但真实运行以该机器人的实际保存值、归一化结果与当前时区为准。
硬休眠/窗口等待不是让操作系统休眠，也不是退出UCP后自动唤醒程序；相关控制器需要继续运行才能再次检查时间。

视频号私信特别区分两种等待：普通窗口或冷却不应切断实时收消息链路，硬休眠则会阻断Tab触发、页面轮询和私信处理。
因此“正在等待”不一定表示所有页面请求都已停止，也不表示可以无限持续回复；查看具体等待原因。
依据：[策略与刷新](../app/services/runtime_policy.py#L204)、[等待判断](../app/services/runtime_policy.py#L373)、[视频号硬休眠](../app/platforms/wechat_video/session_controller.py#L2608)。

## 怎么看运行日志和接口详情

1. 点击目标机器人卡片的“日志”，确认标题对应需要排查的机器人。
2. “运行日志”看登录、模块、生成、发送、确认与等待过程。
3. “接口请求”中选一行，查看时间、方法、状态、耗时、路径和可取得的请求/响应详情。
4. 需要反馈时点击“复制日志”或“复制请求详情”，先清理客户信息、Token和本地路径再分享。
5. “清空”清当前窗口显示，不是删除SQLite、Core记录或全部内存历史；再次打开窗口可能重载缓存。

PC机器人运行配置可关闭GUI日志或接口可视化；两项都关闭时卡片日志入口可能隐藏，这不等于机器人没有运行。
日志有截断和数量上限，不是完整永久审计档案；没有看到一条日志不能单独证明从未发生对应动作。
不要把生成Trace、平台发送证据和后台操作日志混为一份记录。
依据：[日志窗口](../app/widgets/log_dialog.py#L26)、[复制/清空](../app/widgets/log_dialog.py#L119)、[按机器人加载](../app/main_window.py#L858)。

## 本地记录保存、故障降级和恢复

`records/`按账号身份保存SQLite对话、评论、分析、回复尝试、来源、确认状态与游标；它不是平台全部历史的自动备份。
写入通过后台队列完成。队列满、写入异常或关闭不及完成时，部分事件可写入本地恢复文件；下次启动记录写入器会尝试重放入库。
恢复事件是补记录，不是把所有曾经发送失败或待确认的消息无条件重新发送。
实际发送是否可重试，仍要结合控制器判断、本地/后端状态和平台可见证据。

若本地记录服务初始化失败，UCP可降级为NullLocalRecordService继续原机器人流程，并记录警告。
所以“界面还在运行”不能证明每条消息都已落盘；磁盘权限、空间、损坏或关闭异常需要单独排查。
恢复文件中的重复、失败与隔离数量也应查看，不要删除未核对资料来制造“恢复成功”的外观。

重启后平台登录Profile、本地记录身份和Core机器人关联都可能影响可恢复范围；仅同名联系人不一定是同一客户。
保留本机资料有助复核，但换电脑或删目录不保证能从Core重建全部本地游标、发送状态及浏览器登录。
依据：[写入与启动重放](../app/services/local_records/writer.py#L58)、[本地服务](../app/services/local_records/service.py#L42)、[降级入口](../app/main_window.py#L115)。

## 有哪些导出或备份入口

当前UCP主GUI没有“对话一键导出”“本地统计报表”“选择SQLite备份”的产品按钮。
日志复制只是诊断文本复制，不能替代客户对话结构化导出。
`LocalRecordService.summary()`和`backup_account()`是开发服务API，当前没有接入主窗口操作；需要扩展时由开发人员另行接线。
PC回复记录与Trace查询属于后端资料，也不等同于本机所有对话的完整备份。

需人工保管本地资料时，先停止机器人并关闭程序，保护records/Profile/config中的私有信息；不要上传真实数据库、Cookie或客户对话到仓库。
依据：[统计服务方法](../app/services/local_records/service.py#L210)、[备份服务方法](../app/services/local_records/service.py#L402)。

## 开发工具和安装包边界

UCP没有与截流客户端相同的业务CLI；正常启动使用 `python run.py`，`tools/verify_*.py`是阶段性开发校验，不是普通用户逐一执行的运营步骤。
源码安装、Python依赖、Windows构建命令、白名单与各参数见[配置与构建](CONFIGURATION.md)。
安装包默认不带真实.env、Core会话、平台Profile和records；安装使用者自行登录与配置。
LICENSE和NOTICE是分发必需文件，构建会检查存在并原样复制到程序分发目录；使用范围以项目许可和第三方原许可为准。
本说明不表示Qt界面、当前平台页面、Windows安装包或macOS应用已经完成实机验收。
