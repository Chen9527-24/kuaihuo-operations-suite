# 业务功能说明

这里按业务能力介绍系统：每个模块由谁使用、配置什么、怎样操作、留下什么记录，以及当前实现到哪里。项目目录回答“代码在哪里”，本目录回答“它能帮助使用者完成什么事”。

所有说明对应当前非商业源码展示版。例子均为虚构操作场景；功能存在、离线检查通过和真实业务闭环完成，是不同的验证层次。

## 2 先理解三种平台操作

| 场景 | 谁先发起 | 执行端 | 与其他模块的区别 |
| --- | --- | --- | --- |
| 自动回复 | 平台出现客户评论或私信 | UCP | 围绕已有消息组织上下文，再决定是否回复 |
| 截流采集 | 运营人员指定监听目标 | 截流客户端 | 收集和处理目标内容，不等于自动形成有效商机 |
| 主动私信 | 操作员选择目标并建立发送任务 | 截流客户端的私信执行链 | 主动向目标发消息，不是对客户来信的自动回复 |

“智能客服”则是回复内容背后的知识、角色、规则和优化能力。它不是第四个必须单独启动的桌面机器人：后台维护配置，Core 处理生成与判断，UCP 执行平台页面操作。

## 3 可以分别学习的三条业务链

### 客服回复

PC 维护账号背景、角色、知识与机器人 → UCP 获取平台消息 → Core 返回回复或其他决策 → UCP 执行发送并同步记录 → PC 查看 Trace 并继续校准。

先阅读自动回复了解执行，再阅读 AI 客服了解知识与生成。固定问答命中、模型生成、人工处理及发送失败需要分别观察，不能只看一个“成功”提示。

### 内容采集与目标处理

PC 配置目标与采集机器人 → 截流客户端读取配置、采集和同步 → 操作员查看记录并决定如何处理 → 如需主动私信，另行建立并执行私信任务。

这是一条可供操作员组织的使用路径，不表示所有采集评论都会自动进入私信任务或 CRM，也不表示采集对象已经同意接收主动消息。

### 官网咨询与客户跟进

PC 编辑并发布内容配置 → 自行接入的官网读取配置和提交咨询 → Core 建立官网来源客户及原始快照 → PC 查看并登记实际跟进。

仓库提供后端与管理界面，没有独立官网前端。来源参数、咨询数量和客户状态仅记录相应信息，不自动证明渠道效果或销售收入。

## 4 不同角色建议怎样阅读

- 想了解项目功能：先看本页，再按感兴趣的模块进入详细说明。
- 想自己搭建：先看 [公共管理](PLATFORM_ADMINISTRATION.md)、[配置说明](../CONFIGURATION.md) 和 [启动顺序](../QUICK_START.md)，再选择一条业务链验收。
- 想研究 AI 客服：按自动回复 → 智能客服 → 仿真/Trace → UCP 发送与记录阅读。
- 想研究采集执行：按截流采集 → 主动私信 → 后端机器人接口与桌面任务执行阅读。
- 想做二次开发：每篇末尾都有页面、接口和源码入口；先明确业务状态和数据边界，再修改实现。

## 5 配置和数据的共同原则

真实服务地址、密钥和身份由使用者填写；登录会话由自己的环境生成。演示数据不得被描述成客户案例或业务效果。

后台登录、平台登录、媒体账号资料、客服背景和商机客户是不同对象。后台角色权限也不同于 AI 客服的回复角色，详见公共管理说明。

各篇的“当前边界”描述会影响自行搭建的实际前提。总体构建和离线检查结果见 [验证范围](../VERIFICATION.md)。
