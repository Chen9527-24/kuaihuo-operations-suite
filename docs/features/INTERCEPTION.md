# 内容与评论采集功能

截流功能用于把指定抖音主页或作品中的内容、评论整理为可核对的捕获记录，供运营人员继续筛选、分析和跟进。
“截流”是项目中的业务名称；采到评论不等于找到采购人、有购买意向、获得联系许可或形成客户。
当前正式桌面适配器仅实现抖音。快手、小红书、TikTok入口已禁用，保留的选择器文件仅供后续扩展参考。
使用、部署与分发应遵守[仓库许可](../../LICENSE)；下文讲解现有功能，不表示当前平台实机已经验收。
正式 Core 机器人、独立采集、续传和调试子命令的区别及示例见 [命令行指南](../../interception-bot/docs/CLI.md)。

## 业务上可以做什么

- 维护一组需要观察的主页，按配置查找近期作品。
- 直接指定若干作品，围绕这些作品整理评论。
- 提取作品描述、可见文字或语音转写，辅助判断作品是否与业务相关。
- 保存评论用户标识、昵称、评论内容、时间及可取得的作品背景。
- 将采集结果同步到管理后台，查看意向分析状态、建议和草稿。
- 对中断的采集恢复执行，或仅补传已经保存在本地的数据。

项目没有根据公开评论自动确认采购身份，也没有承诺覆盖平台全部作品、全部评论或全部历史数据。
捕获记录入库、意向分析或后续私信回报 `SENT`，都不会自动新建 CRM 客户、生成客户跟进历史或推进销售阶段；商机客户由独立模块维护。

## Core、PC和桌面客户端分别负责什么

| 部分 | 负责的操作 | 不应混淆的边界 |
| --- | --- | --- |
| PC管理后台 | 创建机器人、维护监听目标和参数、查看捕获数据与分析结果 | 页面点击启动不等于远程拉起操作者电脑上的采集进程 |
| Core Nexus | 租户权限、机器人配置、作品判定接口、捕获数据入库、后续意向分析 | 后端运行不替代本地平台账号登录 |
| 截流桌面客户端 | 登录Core、读取配置、打开平台、采集、生成本地结果并同步 | 桌面程序需要在执行电脑上实际运行 |
| 平台账号 | 提供当前登录身份可以看到的页面和内容 | 账号可见范围、页面变化与验证提示会影响结果 |

PC入口是 `/robots/intercept`，页面包含截流机器人、主动私信机器人、捕获数据、提示词配置和任务队列。
界面入口见[路由](../../kf-pc/src/router/index.ts)与[功能页面](../../kf-pc/src/views/interceptrobotmanagement/InterceptRobotPhasePage.vue#L3)。

## 主页监听与作品监听

| 项目 | 主页模式 `homepage` | 作品模式 `content` |
| --- | --- | --- |
| 输入 | 一个或多个主页地址 | 一个或多个明确的作品地址 |
| 目标数组 | `homepageTargets` | `contentTargets` |
| 作品范围 | 先取得主页作品，再进行时间等筛选 | 直接处理所填作品，不按主页回溯天数选作品 |
| 作品前置判定 | 可按配置调用后端工作流，决定是否继续采评论 | 当前正式链路跳过“是否继续”判定，直接进入评论采集 |
| 典型用途 | 定期复查一组已知主页 | 核对一个明确活动或话题作品 |

同一轮使用一种目标模式。目标对象可带 `url`、标签和 `enabled`；只有启用目标参与执行。
`randomizeTargets`控制本轮目标访问顺序，随机访问不代表跨多轮去重，也不代表平台限流豁免。
作品短链接会尝试解析真实作品标识；跳转失败或页面受限时仍可能无法识别。
目标归一化见[机器人配置](../../interception-bot/src/robot_config.py#L115)，直接作品分支见[运行器](../../interception-bot/src/robot_runner.py#L365)。

## 执行时间和采集范围

| 配置 | 业务含义 |
| --- | --- |
| `schedule.timezone` | 计算截流执行窗口所用时区 |
| `schedule.runWindows` | 允许执行的一个或多个时间段，支持跨午夜 |
| `schedule.runEveryDays`、`anchorDate` | 按天计算运行周期及首次计划 |
| `homepageLookbackDays` | 主页作品回溯天数，不是评论发表时间过滤器 |
| `collect.maxPosts` | 单次主页作品数量上限；0表示不设数量上限 |
| `collect.maxCommentsPerPost` | 单作品评论数量上限；0仍受时间及页面可见范围约束 |
| `collect.maxTargetMinutes` | 单个主页或作品处理时长预算 |
| `collect.commentFetchMaxSeconds` | 单作品评论采集额外时间上限，0表示不另加此限制 |
| 冷却与分页停顿参数 | 作品之间、目标之间、评论翻页之间的等待节奏 |

“0不设数量上限”不能理解为无限采集；页面、登录态、时间预算与失败都会使任务结束。
正常周期检查会读取本地完成记录，只有完整成功的终态才推进运行周期。
GUI手动启动追加 `--ignore-run-cycle`：会跳过按天周期，仍检查当天允许时段；不要把它写成所有时间限制都失效。
这些配置是执行门槛，不是关闭桌面客户端后仍可运行的云端计划任务。
依据：[周期判断](../../interception-bot/src/robot_config.py#L257)、[GUI启动参数](../../interception-bot/src/gui_app.py#L2992)、[完成条件](../../interception-bot/src/cli.py#L415)。

## “最近N天”怎样判断

主页模式综合接口/页面可得的发布时间，以及作品标识推算出的候选时间。
有效候选中只要有一个落在回溯范围内，作品就可能被保留；时间源冲突会记入诊断。
全部有效时间都过早的作品会被过滤，明显异常的未来或过早时间也会被排除。
如果时间字段缺失或全部解析失败，当前容错逻辑会保留作品，避免页面格式变化把整组作品误过滤。
因此结果并不是经过逐条人工确认的严格“N天内清单”；需要查看筛选日志与原作品时间。
恢复已有作品计划时也不等同于重新按当天回溯范围筛选一遍。
具体规则见[时间候选筛选](../../interception-bot/src/account_sync_service.py#L1430)。

## 语音转写、页面文字和作品判定

### 语音转写

语音路径尝试获取媒体音频，必要时处理视频，再用本地模型转写。
使用者需要自行准备ffmpeg、可用的本地Whisper模型及适合的设备配置。
展示版默认不指定模型、不允许自动下载；配置缺失会报错，不能把“没有识别结果”当成作品没有口播。
临时媒体会按清理策略处理，业务复核可查看转写、状态和错误字段。

### GUI文字桥接

特定GUI兜底链路会读取工作区的可见文字、标题或描述，标记为 `GUI_TEXT_ONLY`。
该文字可能写入 `speechTranscript` 字段，但不是从音轨听写得到的口播全文。
比较作品时，应同时检查 `speechStatus`，不要只看字段中有文字便认定转写成功。
依据：[GUI内容处理](../../interception-bot/src/account_sync_service.py#L254)、[文字状态赋值](../../interception-bot/src/account_sync_service.py#L789)。

### 作品前置判定

主页模式可启用 `workDecision.enabled`，把作品背景交给Core，返回继续或跳过的建议。
展示版要求明确填写自己的 `workflowId`；未填写时返回 `CONFIG_MISSING`，不会调用隐含的后端默认工作流。
主页处理链路中，语音失败、空转写、工作流调用失败可按配置选择跳过或继续；缺失workflowId不能用失败继续策略绕过。
直接作品模式会记录语音失败或禁用状态，但当前仍可继续采评论；不要把主页失败策略套用到这条路径。
作品前置判定只回答“是否继续处理这个作品”，不等于评论者的意向分析。
依据：[判定前提](../../interception-bot/src/account_sync_service.py#L977)、[后端判定接口](../../core-nexus/src/modules/robots/robots.controller.ts#L521)。

## 评论采集、筛选和去重

正式主页与直接作品链路当前显式使用 `collect_replies=False`，主要采集一级评论。
底层保留展开回复及多级评论代码，但这不构成当前正式流程默认采二级评论的承诺。
采集通过平台页面/响应及兜底路径读取可取得的数据，受评论分页、页面加载和时间预算影响。
评论为空可能是确实没有可见评论，也可能是登录、接口或页面识别失败，应结合阶段日志判断。

上传前按“评论用户＋评论时间＋规范化评论文本”构造业务去重键；字段不足时尝试使用平台评论标识。
同批重复行会补齐首条缺失字段，而不是任意覆盖已有内容。
后端在租户和机器人范围内继续查重并补空字段；不同机器人采到同一评论不应被概括为全系统只保留一条。
字段缺失或时间表达改变会影响去重判断；去重不等于识别同一自然人或客户公司。
依据：[一级评论开关](../../interception-bot/src/account_sync_service.py#L620)、[客户端去重](../../interception-bot/src/core_nexus_client.py#L658)、[数据库唯一范围](../../core-nexus/prisma/schema.prisma#L2152)。

## 怎样同步到管理后台

1. 将作品和评论整理为精简行，保留作品地址、用户标识、评论、时间、可见地区及分析背景等字段。
2. 默认不把整个浏览器响应或庞大原始抓取对象直接作为上传请求体。
3. 默认每批至多50行，并按约60,000字节的请求体预算分批；超长字段可能截断。
4. Core逐行入库，返回新增、更新、跳过、失败数量及有限的失败行详情。
5. 本地保存待传载荷与批次状态，便于网络中断后继续同步。

预检查作品行的上传默认关闭；只做完作品检查但没有评论，不能据此认为PC一定会出现一条评论捕获记录。
“同步完成”也不等于每条数据都新增成功，应核对更新、跳过和失败统计。
依据：[精简字段](../../interception-bot/src/core_nexus_client.py#L530)、[双重分批](../../interception-bot/src/core_nexus_client.py#L369)、[逐行入库](../../core-nexus/src/modules/robots/robots.service.ts#L1053)。

## 上传后的意向分析与人工筛选

本次新增或被补充更新的捕获记录，可进入Core的异步意向分析流程，结果稍后显示在PC。
需要自行配置模型/工作流、业务背景和提示词；源码不附带可用服务凭据。
意向等级、分值、建议私信、切入说明和草稿是分析输出，需要人工结合评论上下文复核。
历史分析失败数据不会自动混入每次新上传：PC“提取失败数据”先建待重试批次，再由操作员单批或全部重试。
从捕获记录继续创建私信任务是另一个明确操作，见[主动私信功能](LEAD_PRIVATE_MESSAGE.md)。
依据：[入库后分析](../../core-nexus/src/modules/robots/robots.service.ts#L1118)、[失败批次页面说明](../../kf-pc/src/views/interceptrobotmanagement/InterceptRobotPhasePage.vue#L537)。

## 本地会留下什么

### GUI 设置、启停和日志

登录自己的 Core 并选择租户后，在“截流 / 私信”分类中刷新列表、选择对应机器人。Core 身份和右侧平台页面的登录状态分开核对，后端运行状态变化不会自动在另一台电脑启动客户端进程。

右上设置可修改 Core 地址、会话缓存位置、默认租户、日志/接口显示和自动恢复，并可检查运行时。系统环境和 `.env` 地址优先于 GUI 保存值；改变地址后，应退出并重新登录正确环境，不会自动改写已登录客户端的全部身份。

卡片“停止”与后台“暂停后续领取”不是同一动作。截流运行中先请求安全停止，超时后可能强制结束进程；主动私信子进程的停止路径通常直接结束，不能据此撤回已经发送的消息。

卡片日志可查看运行和接口信息、复制内容与清空窗口。窗口清空不等于删除本地文件、Core 捕获记录或私信任务，复制反馈前应先清理私有信息。
依据：[GUI 设置](../../interception-bot/src/gui_app.py#L1813)、[停止逻辑](../../interception-bot/src/gui_app.py#L4531)。

### 导出最近的作品判断表

1. 选择截流机器人卡片，在未运行时打开“•••”更多菜单。
2. 选择“导出”，由客户端查找本机最近匹配的作品判断日志。
3. 按需要保存为 XLSX、CSV 或 TXT；没有相应日志时会提示无数据。
4. 核对表格中的作品、判断和失败信息，不把它当成全部评论或全部后台捕获记录。

这个导出使用本机作品日志，不是 PC 捕获评论表，也不是 CLI 的 `comments.csv`。保存对话框默认可能指向项目根目录，建议选已忽略的 `output/exports/` 或仓库外位置，避免把实际运行资料加入公开提交。
卡片“恢复任务”和“继续同步”也位于更多菜单，需有相应本地资料且当前未运行；二者区别见下文。
依据：[卡片更多操作](../../interception-bot/src/gui_app.py#L1592)、[导出数据来源与格式](../../interception-bot/src/gui_app.py#L4618)。

### 输出文件的用途

| 内容 | 主要用途 |
| --- | --- |
| 运行结果及阶段summary | 核对本轮处理的目标、作品、评论和错误 |
| `operation_log/works_log.csv`、jsonl、txt | 按作品记录处理摘要，便于人工对照 |
| `speech_review/`及各作品复核文件 | 区分转写、页面文字、作品判定与失败原因 |
| `sync_payload/capture_rows_payload.json`及preview | 核对待上传数据与可读表格 |
| `sync_payload/sync_state.json`及异常行资料 | 跟踪批次上传、失败隔离与续传 |
| `state/`、`profiles/` | 本机控制、恢复记录和浏览器登录状态 |

输出一般按 `output/<平台>/<账号路径键>/<运行批次>/`归集，路径键可能经过安全化，与显示昵称不完全相同。
具体文件随执行路径和结果变化；不能要求每一轮都有所有类型。
这些目录可能含用户资料、评论、媒体文字和Cookie，不属于公开演示数据，也不随安装包发布。

## 恢复任务与继续同步

| 操作 | 适用情况 | 会做什么 |
| --- | --- | --- |
| 恢复任务 | 主页或作品处理过程中退出、停止、异常 | 读取作品级断点，跳过已完成项，继续尚未处理的目标/作品，之后同步 |
| 继续同步 | 采集结果已存在，最后上传中断或失败 | 读取本地载荷，跳过已成功批次继续传输；不重新打开作品采评论或转写 |
| 新启动 | 开始一个新的观察批次 | 重新按当前配置执行，不能代替核查旧批次是否完整 |

安全停止优先保存断点；超时被强制结束、磁盘资料丢失或本地状态损坏时，恢复仍可能失败。
续传可能隔离异常单行或把失败批次二分定位；必须查看异常行文件，不能只以程序退出码判断所有行都已入库。
恢复依赖本机保留的输出与状态，换电脑或删目录后不会自动从后端重建全部本地断点。
依据：[恢复记录](../../interception-bot/src/intercept_recovery.py#L195)、[继续同步入口](../../interception-bot/src/cli.py#L660)、[批次续传](../../interception-bot/src/sync_resume.py#L301)。

## 自行部署后的操作顺序

1. 完成Core与PC配置，确认租户、操作员权限和数据库迁移可用。
2. 在PC创建抖音截流机器人，选择主页或作品模式，填写自己有权处理的测试目标。
3. 先设置小范围、有限数量和短任务窗口，决定是否需要语音和前置作品判定。
4. 参照[桌面配置说明](../../interception-bot/docs/CONFIGURATION.md)填写自己的Core地址、浏览器和模型配置。
5. 启动桌面客户端，登录Core并选择租户，在对应机器人完成平台登录。
6. 在允许时段启动，观察目标切换、筛选、转写或文字状态、评论数量和同步统计。
7. 回PC核对捕获行、来源作品、分析状态及失败信息，再决定是否导出或创建其他任务。
8. 若中断，先判断是采集未完成还是仅同步未完成，再选择恢复任务或继续同步。

## 虚构操作示例

假设测试团队有权使用一个测试主页和两条自建作品，想观察其中的产品咨询评论。
可先用作品模式只填这两条作品，把每条评论上限设为20，并关闭不需要的语音功能。
若改成主页模式，设置回溯7天后，还要复核时间缺失而被保留的作品，不能直接把结果称为“过去7天的全部咨询”。
同步后由测试人员核对评论中的具体问题，再标记值得了解的记录；“想了解”之类措辞也不自动证明购买能力。
示例中的目标、数量和判断仅用于说明步骤，没有实际采集、线索数量或成交效果。

## 常见失败与定位

| 现象 | 优先核对 |
| --- | --- |
| 点击启动后跳过 | 当前时段、逻辑日期、周期及GUI是否绕过按天周期 |
| 主页作品为0 | 登录状态、作品加载、时间筛选及接口/DOM兜底日志 |
| 有文字却没有真实转写 | `speechStatus`是否为GUI_TEXT_ONLY，媒体与模型是否可用 |
| 作品有记录但没有评论 | 作品判定、失败策略、一级评论可见性、数量及时间预算 |
