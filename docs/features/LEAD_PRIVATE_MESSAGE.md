# 线索主动私信功能

主动私信功能把操作员选中的捕获记录组织为任务，由本地桌面客户端访问目标用户主页、执行发送，再把执行结果回报Core。
它用于主动发起一段对话，机器人类型为 `LEAD_PRIVATE_MESSAGE`，当前桌面实现仅支持抖音。
采集到评论、模型判断“建议私信”或任务创建成功，都不代表用户同意接收营销消息，也不证明对方是采购人。
使用和分发应遵守[仓库许可](../../LICENSE)，目标、内容及账号的使用权限由部署者自行确认。

## 和其他功能有什么关系

| 功能 | 起点 | 后续操作 |
| --- | --- | --- |
| 截流采集 | 指定主页/作品 | 取得评论与作品背景，形成捕获记录 |
| 评论意向分析 | 已入库捕获记录 | 生成等级、建议、切入说明和草稿，供人工参考 |
| 主动私信 | 人工选定的捕获记录与确认文案 | 创建任务、领取、访问目标主页并执行发送 |
| UCP私信自动回复 | 平台上已有的客户消息/会话 | 采集上下文、请求Core回复、处理后续消息与记录 |

主动私信不是UCP自动回复的另一名称。两者的机器人类型、任务入口、执行流程和发送确认设计都不同。
不能把UCP的分段回复、插话中止、会话记录能力直接算到主动私信任务上。
当前捕获入库和私信结果回报不会自动创建 CRM 客户、跟进记录或推进销售阶段，商机客户需要通过独立模块维护。

## 从哪里操作

PC菜单“竞品截流”的 `/robots/intercept` 页面同时提供主动私信机器人、捕获数据和主动私信任务队列。
`/robots/private-message` 是原私信自动回复管理入口，不是本功能的主要任务创建页面。
桌面端在截流客户端中切换“截流 / 私信”，私信列表加载 `LEAD_PRIVATE_MESSAGE` 配置。
后台页面见[截流功能页](../../kf-pc/src/views/interceptrobotmanagement/InterceptRobotPhasePage.vue#L87)，桌面执行入口见[工人run](../../interception-bot/src/private_message_worker.py#L170)。

## 谁负责哪一步

| 部分 | 职责 |
| --- | --- |
| 操作员 | 核对目标来源、评论上下文、触达必要性、最终内容及执行范围 |
| PC | 筛选记录、维护执行机器人、编辑文案、创建批次、查看与管理队列 |
| Core | 租户隔离、记录查找、任务校验、去重/冷却、领取和结果存储 |
| 桌面客户端 | 平台登录、读取配置、领取任务、打开目标主页、输入和点击发送 |
| 平台 | 决定账号可见范围、入口可用性和实际消息处理结果 |

Core不会仅因保存了机器人便在服务器上替用户登录平台；PC也不会远程自动打开一台未运行客户端的电脑。

## 第一步 复核捕获记录

捕获数据来自[内容与评论采集](INTERCEPTION.md)，可以按关键词、平台、截流机器人、意向等级等条件缩小列表。
操作员可对照用户评论、来源作品、用户标识/主页、分析状态、建议私信和草稿，再勾选记录。
意向等级和建议来源于当前配置的分析规则/模型，是判断线索，不是经核验的买家身份或授权证明。
当前后端创建任务时没有把“建议私信=true”、某个意向等级或安全评分设为通用的强制准入门槛。
因此不要认为界面能勾选的所有行都已通过业务审批；筛选与确认仍需要操作员完成。

只保留昵称而没有可用用户标识或主页链接的记录，可能无法创建任务或无法打开私信入口。
后端也不会把“来源作品作者”自动当成评论用户；目标应核对为需要联系的评论者。
依据：[捕获列表](../../kf-pc/src/views/interceptrobotmanagement/InterceptRobotPhasePage.vue#L121)、[候选校验](../../core-nexus/src/modules/robots/robots.service.ts#L5084)。

## 第二步 建立主动私信机器人

一个机器人是一组执行参数，不是系统随附的可用平台账号。
后台创建时填写名称、平台、是否启用和备注，执行参数可展开调整。
PC参考样例默认停用并暂停，填入样例不会自动保存、创建任务或发送。
默认业务参数与样例参数不同，应以实际保存值为准；不能把参考数字当成平台允许的发送额度。

| 参数 | 业务作用 |
| --- | --- |
| `enabled`、`paused` | 是否可用及是否暂停后续领取 |
| `minSendIntervalSeconds`、`maxSendIntervalSeconds` | 每条执行前随机等待的秒数区间 |
| `workStartTime`、`workEndTime` | 后端允许领取的时间段 |
| `sleepStartTime`、`sleepEndTime` | 可选的后端休眠时间段 |
| `dailySendLimit`、`hourlySendLimit` | 后端按已回报SENT的任务统计额度 |
| `userTouchIntervalDays` | 创建新任务时，同租户已发送用户的触达冷却天数 |
| `claimBatchSize` | 每轮请求领取数量，接口限制最多20 |
| `maxConsecutiveFailures` | 当前实现用于单任务自动重领上限，实际语义见后文 |
| `defaultMessageTemplate` | 捕获记录和人工确认都没有可用草稿时的兜底文案 |

时间段按Core进程本地时间计算，日额度使用数据库日期边界；部署时应核对服务与数据库时区。
这与截流配置中的显式 `schedule.timezone` 不是同一套计算入口。
依据：[PC参考样例](../../kf-pc/src/views/interceptrobotmanagement/InterceptRobotPhasePage.vue#L1200)、[配置归一化](../../core-nexus/src/modules/robots/robots.service.ts#L5009)。

## 第三步 确认草稿与创建任务

1. 在捕获数据中勾选需要处理的记录，点击“创建主动私信任务”。
2. 对照来源评论和作品，逐条查看预填内容，可在创建弹窗中修改。
3. 选择一个主动私信机器人，并填写计划开始和结束时间。
4. 提交后查看“已创建 / 已跳过”数量和各记录原因，不要仅看提交成功提示。
5. 到任务队列核对目标、文案、执行机器人和时间窗口，再决定何时启用本地执行。

文案选择顺序大致为：本次人工传入内容 → 捕获记录中的草稿/最终内容等兼容字段 → 机器人默认模板。
默认模板支持 `{{nickname}}`、`{{comment}}`、`{{contentTitle}}`，这些替换不代表内容已经适合发送。
PC创建弹窗会提交逐条文案覆盖；后端据此可标记为人工创建，不能因为原先由AI预填就保留全部AI生成来源结论。
任务保存来源评论、作品、目标、草稿与最终内容；可取得时也保留意向、风险和生成追踪等元数据。

后端接口接受机器人数组，但当前实现实际使用第一个机器人；PC界面目前也只选择一个。
创建时要求计划结束晚于开始；尚未到开始时间的任务为 `WAITING_WINDOW`，否则为 `PENDING`。
依据：[创建弹窗提交](../../kf-pc/src/views/interceptrobotmanagement/InterceptRobotPhasePage.vue#L1833)、[任务创建](../../core-nexus/src/modules/robots/robots.service.ts#L4615)、[文案选择](../../core-nexus/src/modules/robots/robots.service.ts#L5114)。

## 创建时怎样避免重复和过度触达

后端检查捕获记录存在、目标可定位、文案非空，并检查未完成任务。
未完成状态包括 `PENDING`、`WAITING_WINDOW`、`CLAIMED`、`RUNNING`。

| 情况 | 当前处理 |
| --- | --- |
| 同一捕获记录已有未完成任务 | 跳过创建 |
| 同租户同一评论标识已有未完成任务 | 跳过创建 |
| 同租户同一用户标识已有未完成任务 | 跳过创建 |
| 同租户该用户在配置天数内已有SENT记录 | 冷却天数大于0时跳过创建 |
| 只有主页链接，没有稳定用户标识 | 可以形成目标，但按用户标识计算的去重/冷却不能完整覆盖 |

冷却以任务表中的SENT记录为依据，不会读取使用者在其他工具或人工发送的全部历史。
这些检查主要发生在新任务创建时，不能当作每次重试前都重新完成同样的业务审批。
并发、记录缺失和平台身份变化下也不能承诺自然人级别的绝对去重。
依据：[重复与冷却校验](../../core-nexus/src/modules/robots/robots.service.ts#L5131)。

## 第四步 本地领取和执行

1. 在自己的电脑启动截流桌面客户端，登录Core并选择对应租户。
2. 进入“私信”分类，选择已经配置的抖音主动私信机器人。
3. 在本机完成平台登录，确认使用的是期望发送账号，而不是另一个机器人的身份。
4. 客户端先读取运行配置，停用或暂停时不开始领取；正式路径先验证可用的抖音登录态。
5. Core检查机器人状态、时段、额度及任务计划窗口，返回本轮可领取任务。
6. 每条任务执行前随机等待，然后打开目标主页、找到资料区私信入口、输入确认文案并点击发送。
7. 客户端回报执行结果；下一轮重新读取启用/暂停配置，再尝试领取。

同平台、同机器人显示名称可用于匹配并复制登录资料到独立执行Profile，不同名称不应当成同一平台身份。
当前默认使用独立Playwright页面执行点击，GUI右侧工作区主要展示任务目标；不能以GUI页面可见就推断执行上下文已登录。
桌面程序连续空领取达到退出条件后会结束本轮，启动一次不等于永远常驻等待所有未来任务。
依据：[登录资料复用](../../interception-bot/src/private_message_worker.py#L239)、[执行循环](../../interception-bot/src/private_message_worker.py#L728)、[打开目标与发送](../../interception-bot/src/private_message_worker.py#L820)。

## 发送、确认和SENT状态应怎样理解

当前默认Playwright路径点击发送后等待约1.2秒，只要流程没有抛出异常，就返回执行成功并回报 `SENT`。
没有完整的平台发送回执校验、消息逐条回显确认或收件人已收到/已读验证。
因此SENT表示客户端回报的发送执行结果，不能写成“平台已确认送达”或“用户已阅读”。
若点击成功但结果回报中断，平台实际状态和任务表可能不同；再次领取/重试前应先核对实际会话，避免重复发送。
生成的claimToken不构成完整发送幂等证明，当前report接口也没有基于该Token的完整领取所有权确认。
依据：[点击发送](../../interception-bot/src/private_message_worker.py#L1897)、[执行返回](../../interception-bot/src/private_message_worker.py#L872)、[结果回报](../../core-nexus/src/modules/robots/robots.service.ts#L4933)。

## 任务状态和操作

| 状态 | 业务含义或实际行为 |
| --- | --- |
| PENDING | 待领取，仍需满足计划时间与机器人条件 |
| WAITING_WINDOW | 创建时计划开始在未来，到时可被领取 |
| CLAIMED | 已领取；超过10分钟的旧领取记录可再次被领取 |
| RUNNING | 状态枚举保留，当前默认工人没有逐条必然上报此中间态 |
| SENT | 客户端回报执行成功，送达边界见上文 |
| FAILED | 执行失败并带原因；符合次数等条件可被自动重领 |
| SKIPPED / BLOCKED | 保留的跳过/拦截状态；默认工人一般回报SENT或FAILED |
| CANCELED | 取消的未结束任务，不再按正常待领取状态处理 |
| EXPIRED | 过期状态可记录；超过计划结束即不再领取，但不保证每行自动改为EXPIRED |

队列支持查看详情、修改文案、取消、重试和删除。`CLAIMED`、`RUNNING`、`SENT`不能编辑文案。
重试允许FAILED/BLOCKED/EXPIRED/SKIPPED/CANCELED，主要将状态改回PENDING并清领取/错误字段，不延长原计划窗口，也不清零发送次数。
取消对已被视为终态的行会直接返回原状态；例如FAILED行仍可能按失败重领规则处理，暂停机器人比假定“取消所有失败”更明确。
取消也不是撤回已经发送的平台消息；对已领取、正在执行的任务，不能据此保证客户端立即停止点击发送。
依据：[队列页面](../../kf-pc/src/views/interceptrobotmanagement/InterceptRobotPhasePage.vue#L300)、[取消重试与编辑](../../core-nexus/src/modules/robots/robots.service.ts#L4777)。

## 额度、自动重试、暂停与恢复的真实规则

- 日/小时额度以该机器人SENT行计算；不是平台批准额度，也不是全平台账号所有发送行为的总量。
- 小时额度当前只在领取前检查是否已达上限，本批数量按剩余日额度和20条裁剪，未按剩余小时额度裁剪；因此它不是严格的批量小时上限，领取批次可能超过当时剩余额度。
- 额度和工作/休眠窗口主要在领取时检查；已领取批次内不会每条重新完整检查，批量和等待会影响实际执行时刻。
- 失败任务的自动领取阈值为 `max(10, maxConsecutiveFailures)`，按单任务sendAttemptCount计算，不是连续失败N次自动暂停机器人。
- 自动领取优先待处理任务，其后为未到阈值的FAILED，再处理超过10分钟的旧CLAIMED记录。
- PC“暂停”修改后端paused配置，主要阻止下一轮领取；已领取批次不会在每条发送前重新检查paused。
- “恢复”允许后续领取，不自动扩展过期窗口、不恢复已经删除的任务，也不替用户重新登录平台。
- 领取使用数据库行锁减少同时取到同一行，但发送回报、取消、重试和失联之间仍不构成严格一次且仅一次的交付机制。

依据：[领取规则](../../core-nexus/src/modules/robots/robots.service.ts#L4864)、[暂停设置](../../core-nexus/src/modules/robots/robots.service.ts#L5070)、[客户端逐批检查](../../interception-bot/src/private_message_worker.py#L740)。

## 失败、记录和恢复判断

| 现象 | 核对重点 |
| --- | --- |
| 创建数少于选中数 | 缺失目标/文案、已有未完成任务、同用户冷却、租户数据范围 |
| 一直领不到 | enabled/paused、机器人状态、Core时区、额度、计划窗口和失败次数 |
| 领到后失败 | 平台登录、目标主页、私信入口、输入框/发送按钮以及页面变化 |
| 平台有消息但队列失败或仍领取中 | 优先核对真实会话和结果回报，勿直接批量重试 |
| 暂停后仍有个别发送 | 检查是否已在暂停前领取整批，以及本地执行是否真正停止 |

Core保存尝试次数、最后发送时间、SENT时间、错误和原始执行结果，PC详情用于对照任务与失败。
本地可能保存私信调试JSON、HTML、截图及Profile/Cookie；这些是私有运行资料，不作为公开样例或安装包内容。
若平台发送状态无法确认，应先人工核对，不能用重试次数代替确认。

## 虚构操作示例

假设测试人员在自建作品下，用自己控制的测试账号留言，并有明确的测试发送安排。
操作员在捕获数据中只勾选这条测试留言，确认目标是该测试账号，创建一条内容已人工核对的任务。
选择一台已登录正确抖音账号的桌面客户端执行，把每轮领取设为1，并在有效窗口中启动。
回报SENT后，测试人员到真实会话中核对是否出现对应内容，再检查PC任务记录；这一步不由当前SENT字段替代。
这个示例没有真实用户、成交或转化数据，也不表示可把未取得许可的公开评论批量转换成营销对象。

## 关键接口与源码入口

以下路径均在Core的 `/api/v1` 下，需要自己的身份、租户和权限配置。

| 接口 | 用途 |
| --- | --- |
| GET/POST/PATCH `/robots/lead-private-message...` | 管理主动私信机器人 |
| GET `/robots/lead-private-message/:id/runtime-config` | 桌面读取执行配置 |
| POST `/robots/lead-private-message/:id/pause`、`resume` | 暂停/恢复后续领取 |
| POST `/robots/lead-private-message-tasks` | 从捕获记录创建任务批次 |
| POST `/robots/lead-private-message-tasks/claim` | 领取符合条件的任务 |
| POST `/robots/lead-private-message-tasks/report` | 回报执行结果 |
| PATCH `/robots/lead-private-message-tasks/:id/message` | 修改尚可编辑的任务文案 |
| POST `.../:id/cancel`、`.../:id/retry` | 取消或请求重试 |

详见[后端接口](../../core-nexus/src/modules/robots/robots.controller.ts#L56)、[桌面接口客户端](../../interception-bot/src/core_nexus_client.py#L186)与[自行配置](../../interception-bot/docs/CONFIGURATION.md)。
