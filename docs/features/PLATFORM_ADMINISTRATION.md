# 账号权限与公共服务

这部分为任务、客服、采集等业务提供公共基础：谁可以登录、在哪个租户操作、可以看到哪些菜单和执行哪些动作，以及文件、短信和微信能力怎样接入。

它主要由 Core Nexus 和 PC 管理后台组成。H5 成员和平台网页登录使用各自的身份体系，不是拿一个后台账号就自动获得所有入口。
机器人设备、配对、扫码授权及心跳的完整生命周期见 [高级管理工具](ADMIN_TOOLS.md)；H5 主体与任务账号的限制、停用、手机号释放等操作见 [成员管理指南](H5_MEMBER_GUIDE.md)。

## 1 先分清系统中的不同账号

| 名称 | 代表什么 | 主要在哪里维护 |
| --- | --- | --- |
| 后台账号 | 登录 PC 或桌面客户端、取得后台角色与权限的操作员 | 系统管理 → 账号管理 |
| 租户 | 后台账号可进入的业务组织或管理范围 | 系统管理 → 租户管理 |
| H5 成员 | 领取任务、提交证明、查看收益和申请提现的参与者 | H5 与运营业务 → H5成员 |
| 多媒体账号 | 被运营的媒体账号资料，包括平台、账号标识、名称和定位 | 运营业务 → 多媒体账号 |
| 平台登录账号 | 用户在抖音、视频号等平台实际登录的账号及浏览器状态 | 各桌面客户端的平台页面 |
| 客服账号背景 | 供模型理解“我代表谁、知道什么”的业务资料和适用关系 | 智能客服 → 账号配置 |
| 商机客户 | 需要记录需求、联系人和跟进安排的客户线索 | 运营业务 → 商机客户 |

新增一条多媒体账号资料，不会自动登录平台；新增一份客服背景，也不会自动创建后台账号。这些对象可以在业务中关联，但不能混用其 ID 或把它们当成同一份登录凭据。

## 2 租户、角色与权限如何配合

### 租户

管理员可以创建租户、修改资料、启用或停用，以及软删除。后台账号可以绑定多个租户，登录后只允许切换到已绑定且启用的租户，切换时重新获得相应的登录结果。

任务、机器人和媒体账号等模块会使用租户上下文。不同业务的查询实现不完全相同，不能因此认定整套系统所有数据都已完成租户隔离。例如商机客户和官网配置当前没有按租户拆表或过滤，详见对应功能文档。

### 后台角色

角色用于组合权限，可配置平台或租户作用域、启停状态及权限集合。一个后台账号可以分配多个角色。角色应按实际岗位配置，例如任务操作、任务审核、客服知识维护或系统管理，而不是让所有测试人员长期共用初始化管理员。

这里的“后台角色”控制操作权限；智能客服中的“角色配置”描述回复身份、行为和表达，两者用途不同。

### 目录、菜单与动作

PC 菜单按“运营业务、智能客服、官网管理、系统管理”组织。菜单可见性和页面内动作使用不同权限编码：可以打开某页，不代表可以新增、删除、审核或付款。

“每日任务”被设计为默认可进入页面，但页面内动作仍受权限控制。最终接口授权由后端 Guard 和控制器权限声明处理，前端隐藏按钮不能代替服务端权限校验。

## 3 后台账号可以管理什么

- 创建账号，填写用户名、显示名、联系信息、绑定租户和角色。
- 修改资料、调整可切换租户和角色，启用或停用账号。
- 由有权限的管理员重置密码；用户在个人中心维护自己的资料和头像。
- 登录后获取当前用户信息，刷新登录令牌、切换租户和退出会话。

首次开发初始化的管理员由部署者填写种子配置创建，不提供通用登录密码。管理员初始化和普通后台“新增账号”是不同操作，不能靠反复执行种子来代替日常账号管理。

源码入口：[后台账号接口](../../core-nexus/src/modules/users/users.controller.ts#L63)、[账号创建字段](../../core-nexus/src/modules/users/dto/user-admin.dto.ts#L4)、[登录与切换租户](../../core-nexus/src/modules/auth/auth.controller.ts#L23)。

### PC 页头的快捷账号与个人中心

页头可以切换或添加已成功登录的账号会话，本机最多保存5份。添加快捷会话与服务器新增用户是两件事：先有可登录账号，再将会话加入当前浏览器。

退出当前账号会移除其快捷会话，退出全部会清除本机保存的全部快捷会话；移除保存项不删除服务器用户。切换租户仍限于该账号绑定的可用租户，个人中心用于维护显示名和头像。

权限管理维护目录、菜单和按钮层级，再由角色选择权限集合并分配给后台账号。新增一个菜单权限节点不会自动生成 Vue 页面，实际页面仍需在源码路由中注册。
入口见 [页头账号操作](../../kf-pc/src/components/AppHeader.vue#L77)、[会话管理](../../kf-pc/src/stores/auth.ts#L93)、[路由映射](../../kf-pc/src/router/index.ts#L7)。

## 4 多媒体账号资料

多媒体账号保存平台、平台账号标识、名称、状态、定位和备注。PC 任务配置可以使用账号下拉选项，后台也提供列表、详情、编辑、启停和软删除。

适合记录“这个账号属于哪类内容、叫什么、是否仍在使用”，并为其他业务提供可关联对象。它不负责保存用户提供的网页 Cookie，也不等于平台官方账号授权服务。

自行搭建时先创建自己的测试媒体账号资料，再在任务中选择相应账号。机器人使用另一套平台登录、授权设备和客服账号资料配置，当前表单不选择这里的多媒体账号。公开展示使用虚构资料，不附带真实平台登录态。

源码入口：[字段定义](../../core-nexus/src/modules/media-accounts/dto/media-account.dto.ts#L4)、[账号管理接口](../../core-nexus/src/modules/media-accounts/media-accounts.controller.ts#L15)、[PC 页面](../../kf-pc/src/views/mediaaccountmanagement/index.vue)。

## 5 文件如何供各业务使用

文件服务承担任务封面、提交证明、头像和官网素材等上传与回显。业务一般先取得文件记录，再在保存业务对象时绑定 `fileId`；“上传成功”和“业务保存成功”是两个步骤。

| 入口 | 用途 | 需要注意 |
| --- | --- | --- |
| 后台通用上传 | 已登录操作员上传文件 | 受后台权限控制，临时文件由业务保存时关联 |
| 后台我的文件 | 查看当前操作员上传的文件 | 不是全站任意文件浏览器 |
| H5 公开上传 | 提交领取凭证、证明等无后台账号场景 | 有独立公开控制器，不使用后台菜单权限 |
| 直传签名与完成登记 | 前端向对象存储传文件，再登记系统记录 | 当前接口以 OSS 直传路径为主要说明，不能假定所有存储驱动完全相同 |
| 官网素材上传 | 官网内容编辑使用的受限图片入口 | 与普通上传的类型、大小和业务绑定规则不同 |

源码包含本地存储、OSS 和腾讯 COS 相关实现，部署者根据配置说明选择使用。本地运行可以先用本地文件；线上回显还需要正确的公开资源地址或代理配置。

文件记录、可访问 URL、业务绑定和实际文件对象分别有自己的生命周期。删除一条业务记录时，不应未经实现核对就推断对应文件对象也被立刻删除。

源码入口：[后台文件接口](../../core-nexus/src/modules/files/files.controller.ts#L34)、[H5 文件接口](../../core-nexus/src/modules/files/files-public.controller.ts#L14)、[存储提供者目录](../../core-nexus/src/modules/files/providers/)。

## 6 短信与微信是可选接入服务

### 短信

短信模块支持验证码及任务、结算、提现等业务通知。当前实现的提供方为 `mock` 和 `tencent`；真实腾讯短信需要部署者自己的密钥、签名和模板。

验证码会保存到 Redis，并执行重发间隔、次数和手机号/IP 限制。mock 模式可以返回测试验证码；“短信关闭后跳过发送”不等于已经创建可供验证的验证码，不能把关闭开关作为完整登录测试方案。

相关配置见 [Core 配置说明](../../core-nexus/docs/CONFIGURATION.md)，实现见 [短信服务](../../core-nexus/src/modules/sms/sms.service.ts#L44)。

### 微信

后端提供服务号 OAuth、JS-SDK 签名、小程序登录/手机号/资料缓存、小程序码和跳转链接等接口。H5 分享和授权消费其中一部分能力，提现还有单独的支付与收款环境要求。

这些接口需要自己的微信应用、域名和凭据。仓库没有独立小程序前端，也没有完整的公开官网前端；看到后端入口不能据此认为相应产品可以直接发布。

源码入口：[微信各控制器](../../core-nexus/src/modules/wechat/wechat.controller.ts#L10)。

## 7 字典与操作日志

数据字典维护类别及选项，为界面选择项提供基础数据；它不替代源码中的状态转换或业务规则。修改显示名称，不代表任务、支付或机器人执行逻辑随之改变。

操作日志模块提供带权限的查询接口，可用于查看相应后台操作记录。当前默认 PC 菜单未列独立的操作日志页，不应仅因为存在接口就描述成一个已接入导航的完整日志工作台。

后台操作日志、回复 Trace、平台发送记录和 H5 订单记录是不同类型的数据。排查问题时应先确定是权限操作、生成回复、页面发送还是结算环节，再看对应记录。

源码入口：[字典接口](../../core-nexus/src/modules/dicts/dicts.controller.ts#L13)、[操作日志接口](../../core-nexus/src/modules/operation-logs/operation-logs.controller.ts#L11)、[当前 PC 菜单](../../kf-pc/src/router/menu.ts#L8)。

## 8 建议的首次配置顺序

1. 填写自己的数据库、Redis、JWT 和初始化管理员配置，启动后端与 PC。
2. 登录管理员，确认自己的租户、角色和权限基础数据。
3. 创建一个测试操作员，绑定目标租户，只给本次验证需要的页面和动作权限。
4. 为任务建立虚构媒体账号资料；如需机器人，另配平台授权/登录与客服账号背景，按对应文档建立。
5. 先验证本地上传和回显，再按需要接入对象存储。
6. 任务登录先明确使用 mock 还是腾讯短信，之后再测试微信授权或付款相关能力。
7. 用操作员账号验证可见菜单和动作，不能只用平台管理员检验权限。

这里描述的是配置与阅读顺序，不代表本仓库已经执行过空库初始化、跨租户权限和外部服务的完整验收。实际验证范围见 [验证说明](../VERIFICATION.md)。

## 9 常见问题

| 现象 | 先检查什么 |
| --- | --- |
| 登录成功但看不到某业务菜单 | 当前租户、角色、菜单权限，以及账号/角色是否启用 |
| 能打开页面但操作提示无权限 | 对应动作权限和后端响应，不只看菜单是否可见 |
| 后台创建了媒体账号但客户端仍未登录平台 | 账号资料与浏览器登录是两层配置，需在客户端自行登录 |
| 上传成功但图片看不到 | 文件回显地址、前端资源基址、代理和业务是否绑定文件 |
| mock 配置后 H5 仍不能提现 | H5 手机微信要求、openid、后端提现配置及申请状态 |
| 想让多个客户共用一个实例 | 逐模块核实租户范围；商机和官网等当前共享资源需额外改造 |

## 10 连通诊断与兼容接口

| 能力 | 实际用途 | 接入范围与边界 |
| --- | --- | --- |
| `GET /api/v1/health` | 执行 PostgreSQL `SELECT 1` 和 Redis `PING` | 不是对模型、支付、短信或平台网页的全面健康检查 |
| `POST /api/v1/ai/deepseek-chat/test` | 用后端环境密钥进行 DeepSeek 对话连通测试 | PC 有相关组件与 API 封装，但当前没有注册为默认导航页 |
| `/api/v1/rbac/overview`、`/me/access` | 读取权限概览与当前访问上下文 | 控制器受 admin 角色约束，概览另有权限要求 |
| 短信通知管理接口 | 发送预设业务类型的模板通知 | 只接受服务端规定的 templateKey，不是任意短信正文或任意云模板发送工具 |
| 小程序 audit/release 模式、scene 解析和平台指引 | 支持现有接入方决定模式、解析参数与获取指引 | 属后端兼容能力，不代表附带完整小程序产品 |
| 旧公开任务及兼容接口 | 保留 `app/daily-tasks`、`posts/*`、`claim-comment/*` 等历史接入 | 不属于任务分发 V2；新接入先沿当前 H5 使用的链路，不混用身份规则 |

接口定义见 [健康检查](../../core-nexus/src/modules/health/health.controller.ts#L8)、[AI 连通测试](../../core-nexus/src/modules/ai/ai.controller.ts#L8)、[RBAC 诊断](../../core-nexus/src/modules/rbac/rbac.controller.ts#L15)、[短信通知](../../core-nexus/src/modules/sms/sms-admin.controller.ts#L11)、[旧任务控制器](../../core-nexus/src/modules/daily-tasks/daily-tasks-legacy.controller.ts#L15)。
